# B6 curriculum context and prompt construction

Completed in development on 2026-09-26. **Current scope update, 2026-09-27:** Study uses the published curriculum path and versioned school prompt. Curiosity accepts general learning questions across subjects and languages without a curriculum gate or `topic_check_id`; its prompt version is `direct-curiosity-open-1` and keeps under-15 guidance. B7 generates and saves answers; B8 educator quality evaluation remains. The topic-check details below describe the historical B6 service retained for compatibility, not the current Curiosity answer path.

## Level and topic policy

A Level maps to KG or 1–5 only when its code/name explicitly says KG, Kindergarten, Level/Grade/Class 1–5, or Level I–V. Unknown labels use an under-15-safe profile and need owner mapping before a specific grade is claimed. Curiosity is not gated by account age. The historical B6 topic-check resolver requires an imported Topic or Subtopic phrase on a current published path; the current Curiosity answer route does not call it. One match is ready, multiple matches return up to eight full candidate paths, and no match is out of scope. The resolver does not guess synonyms or semantic matches; any later classifier must validate candidate IDs against the published catalogue.

## Prompt and context

`teaching.service.prepare(db, student_id, session_id, question)` loads the owned session. Study rechecks the selected published Topic ancestry, its optional Subtopic ID, and pinned revision. Current Curiosity assembles a general prompt from owned bounded history without a catalogue lookup. The legacy `prepare` service searches published Subtopic paths per question. A ready result has validated IDs, revision, optional curriculum description/Topic learning outcome and a deterministic prompt. The prompt never claims a citation, grounding or inferred learning outcome. Version `direct-school-1` separates server policy from catalogue data, question and complete-pair history. Limits are 4,000 question characters, eight history pairs, 8,000 history characters and a conservative 16,000-token upper bound measured as UTF-8 bytes plus message overhead. B7 must enforce provider-specific token and response limits. Profile version `kg5-1` caps KG through Level 5 to 60/75/90/110/130/150 words; unknown level caps at 100. These are prompt instructions; B8 must measure actual output.

## Public topic exchange

`POST /api/v1/sessions/{id}/topic-check` requires an `Idempotency-Key` and returns `ready`, `clarification` or `out_of_scope` without a model call. A repeated key and same question replays the current outcome; a changed question with the same key conflicts. `GET` on that path returns a currently valid pending clarification. `GET /api/v1/sessions/{id}/topic-check/history` provides owned cursor pagination. `POST /api/v1/sessions/{id}/clarifications/{clarification_id}` accepts exactly one candidate Subtopic ID or bounded free-text choice such as “the second one”; same-choice replay is safe and a changed choice conflicts. The legacy B6 endpoints remain owned; the current saved-session dialog no longer presents a topic-check gate.

Migration `20260926_13` stores the original Curiosity question, up to eight candidate full paths/revisions, a ten-minute expiry and selected path. Migration `20260926_14` stores one owned topic-check event per idempotency key, its outcome and, when ready, a validated full context snapshot including resolved subject/topic IDs and revision. New questions cancel old pending choices. Continuation checks owner, choice, expiry and current path/revision; an expired or stale choice cannot become ready. Session/account deletion removes both kinds of records. These topic-check records remain historical/legacy. The current B7 Curiosity ask does not bind them and saves null curriculum/subject/topic fields. Study answer turns retain validated curriculum IDs.
